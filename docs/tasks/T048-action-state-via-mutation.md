# T048 — 업무 액션 실행 상태를 DB 명령 기반 mutation으로 전환

- 상태: 진행중
- 생성: 2026-11-01
- 완료: -

## 배경

T041에서 화면의 `useMutation`을 제거하면서 액션 대기·오류 상태를 직접 구현한
`shared/command-execution-store.ts`(대기 개수 카운트·최신 실행 오류)가 대신 소유하게 됐다.
TanStack DB는 쓰기의 성공·실패를 화면에 상태로 제공하지 않는다.

- 설치된 `@tanstack/db` 0.9.2: 행 `$synced`만 있고 트랜잭션 상태를 구독하는 React 훅이 없다.
- `1.0.0-rc.1`: `$hasPendingWrites`, `tx.when('settled')`만 있다. 실패 상태(`$writeStatus`,
  `tx.when('failed')`, `db.mutations`)는 RFC TanStack/db#1625에서 아직 제안 단계다.
- 행이 없는 액션(로그아웃)과 서버 확인 후 반영하는 액션(삭제)은 DB 행으로 진행 중을 알 수 없다.
- 결과적으로 화면이 catch로 실패를 별도 보관하거나 직접 구현한 Store를 유지해야 했다.

변경 명령(`entities/task/commands.ts`, `entities/auth/server-cache.ts`의 `commands`)은 이미
실패 시 예외를 던지고 낙관적 반영·되돌리기를 DB 트랜잭션이 처리한다.

## 작업 내용

계층을 다음과 같이 재정의한다.

- **DB**: 서버 데이터 보관, 낙관적 반영, 실패 시 되돌리기. 화면은 live query로 읽는다.
- **Query (조회)**: 서버 데이터를 가져와 DB 컬렉션에 채운다. 화면은 직접 읽지 않는다.
- **Query (변경 = mutation)**: 업무 액션을 실행하고 그 대기·오류 상태를 제공한다.
  `mutationFn`은 반드시 DB 명령이다 — 서버 호출을 직접 넣으면 DB를 우회한다.

구현:

- `entities/task/context.tsx`의 `useTaskAction(name)`, `entities/auth/context.tsx`의
  `useAuthAction(name)`가 이름 있는 DB 명령을 `useMutation`으로 감싸 반환한다.
  명령 이름을 키로 받아 입력·결과 타입을 명령 시그니처에서 추론한다.
- mutation용 QueryClient는 각 Provider가 서버 캐시 인스턴스마다 만든다. 세션(캐시)이 바뀌면
  mutation 상태도 함께 분리된다.
- 화면은 `useTaskCommands`/`useAuthCommands` 대신 위 훅만 사용한다. 화면에서
  `@tanstack/react-query` 직접 import 금지 규칙(dependency-cruiser)은 유지한다.
- 성공 후 화면 동작(이동, 시트 닫기, draft 정리)은 `mutate(input, { onSuccess })`에 둔다.
- 폼 화면은 `mutateAsync`를 호출하고 제출 상태는 기존처럼 Form의 `isSubmitting`/`formError`를 쓴다.
- `shared/command-execution-store.ts`와 테스트를 제거한다.

기각한 대안:

- 행 `$synced`/`$hasPendingWrites` + catch로 오류만 보관: 로그아웃·삭제 진행 중을 표시할 수 없고
  실패를 화면이 별도 처리해야 한다.
- MutationCache 상태를 로컬 전용 DB 컬렉션에 복사: 같은 상태가 트랜잭션·mutation·복사본
  세 곳에 생기고 정리 로직이 늘어난다.
- 화면에서 `useMutation` 직접 사용: `mutationFn`에 서버 호출을 넣어 DB를 우회하는 실수를 막지 못한다.
- 원격 `claude/wonderful-hopper-pvwhqz`(TanStack DB RC 업그레이드)는 사용자가 불필요하다고 판단했다.
  이 태스크는 main(react-db 0.4.1) 기준으로 진행한다.
