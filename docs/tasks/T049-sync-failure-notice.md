# T049 — 첫 로드 이후 실시간 동기화 실패를 화면에 알림

- 상태: 완료
- 생성: 2026-11-01
- 완료: 2026-11-01

## 배경

첫 로드 이후 SSE 신호로 실행하는 델타 동기화(`transport.changes`)가 실패하면
`entities/task/server-cache.ts`의 `scheduleRetry`가 3초 뒤 재시도만 하고 실패를 어디에도 남기지 않았다.
사용자는 화면이 최신이 아닐 수 있다는 사실을 알 수 없다.

원격 `claude/wonderful-hopper-pvwhqz`(T047)는 TanStack DB 1.0 RC로 올려 live query의 `isSyncError`로
이를 표면화했다. 사용자는 RC 업그레이드는 불필요하고, 현재 main(`@tanstack/db` 0.9.2) 기준으로
동작하길 원했다. 0.9에서는 `ready` 이후 컬렉션을 오류 상태로 바꾸면 `insert`/`update`/`delete`가
막혀 업무 명령이 깨지므로 컬렉션 status로 표현할 수 없다.

## 작업 내용

- 서버 캐시가 `syncError` 읽기 전용 Atom(TanStack Store)을 소유한다. 델타 동기화가 실패하면
  오류를 기록하고, 다음 동기화가 성공하거나 동기화 원본이 모두 정리되면 `null`로 지운다.
- `useTaskSyncError()`가 이를 구독한다. `_app` 레이아웃의 `SyncErrorNotice`가 실패 중에만
  상단 안내를 띄우고, 재시도가 성공하면 사라진다.
- 첫 로드 실패는 기존처럼 Suspense/라우트 오류 경계가 처리한다.

기각한 대안:

- TanStack DB 1.0 RC 업그레이드(T047): RC 의존 없이 현재 설계로 해결할 수 있다.
- 컬렉션 status를 `error`로 전이: 0.9에서 쓰기 명령이 막힌다.
- 로컬 전용 DB 컬렉션에 오류 행 기록: 데이터가 아닌 연결 상태를 DB에 넣게 된다.
