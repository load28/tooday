# T042 — 서버 캐시·클라이언트 Store의 공개 범위와 이름 정리

- 상태: 완료
- 생성: 2026-09-18
- 완료: 2026-09-18

## 배경

`entities/task/data.ts`가 DB 원본·명령·동기화·수명을 한 객체로 노출하고 `context.tsx`가 전체 객체를 화면에 전달한다. 페이지의 `state.tsx`와 `shared/action-state.ts`는 소유 데이터와 수명이 이름에 드러나지 않는다.

## 작업 내용

서버 캐시와 변경 명령을 화면의 별도 접근점으로 제공한다. 캐시 수명 관리는 라우터 조립에 한정한다. 페이지 Store와 실행 상태 Store는 소유 대상을 이름에 명시한다. Store가 명령을 호출해 서버 캐시에 반영하는 것은 허용하되 서버 응답을 Store 원본으로 복제하지 않는다. BFF 동기화 계약은 변경하지 않는다.

## 완료 기준

- [x] 화면 조회·명령에서 원본 DB와 세션 수명 조작을 숨긴다.
- [x] Store와 서버 캐시의 파일·심볼 이름 및 문서를 일치시킨다.
- [x] 타입 검사·기존 회귀 테스트·의존성 검사를 통과한다.

## 작업 로그

- 2026-09-18: 서버 캐시·변경 명령·페이지별 클라이언트 Store로 이름을 정리했다. Context는 조회와 명령만 공급하고 원본 컬렉션과 수명 관리를 감춘다. feature의 서버 캐시 내부 import를 의존성 규칙으로 금지했다.
- 검증: 전체 4개 패키지 typecheck, 웹 47개 테스트, lint:deps 통과. Store → 변경 명령 → 낙관적 DB → 서버 확정값 흐름을 렌더링 테스트로 검증했다.
- 테스트 프로세스는 종료 지연 경고를 출력하지만 exit code 0으로 종료했다. 커밋·푸시는 수행하지 않았다.

> **어시스턴트**: 화면의 접근점을 서버 조회와 변경 명령으로 나눴습니다. Store 이름도 날짜 선택·상태 필터·상세 시트·명령 실행 상태처럼 소유 대상을 명시했습니다. 이제 이 경계를 의존성 규칙으로 고정하고, Store를 통한 저장과 기존 동기화가 유지되는지 검증하겠습니다.
>
> **어시스턴트**: Store에서 변경 명령을 호출하면 낙관적 값이 표시되고, 응답 후 서버 확정값으로 바뀌는 테스트까지 통과했습니다. 전체 타입 검사와 웹 테스트 47개, 의존성 검사도 통과했습니다. 변경 사항과 검증 결과를 문서에 정리하고 있습니다.
