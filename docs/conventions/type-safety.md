# 타입 안전성 — 컴파일 타임에 어긋남을 잡는 설계

## 원칙

런타임에 터지거나 리뷰어의 눈에 의존할 어긋남은, 가능한 한 **타입이 정확히
추론되는 구조**로 만들어 tsc가 잡게 한다. 값의 계약(키, 파라미터, 허용 범위)을
한 곳에 선언하고 나머지는 전부 그 선언에서 파생시킨다.

- **단일 선언, 파생 사용**: 계약(스키마)을 한 번 선언하고 사전·클라이언트·서버가
  모두 그 타입에서 파생되게 한다. 같은 정보를 두 곳에 손으로 쓰면 어긋나도 아무도 모른다.
- **추론을 우회하지 않는다**: `any`, 근거 없는 `as` 캐스팅, `Record<string, string>`
  같은 넓은 타입으로 좁은 계약을 뭉개지 않는다. 캐스팅이 필요해 보이면 설계를 의심한다.
- **문자열보다 리터럴/브랜드**: 허용값이 정해진 곳은 `string`이 아니라 리터럴 유니온,
  `satisfies`, 브랜드 타입으로 선언해 오타가 컴파일 에러가 되게 한다.

## 코드베이스의 실례

- **i18n** (`apps/web/src/shared/i18n/`): 문구 구조와 플레이스홀더를 `MessageSchema`에
  한 번만 선언하고, locale 사전은 `defineMessages<MessageSchema>()`로 빌드한다.
  키 누락/초과, 선언에 없는 `{플레이스홀더}`, 파라미터 오타가 전부 컴파일 에러다.
  `format()`은 문구의 브랜드 타입에서 요구 파라미터를 추론한다.
- **라우트 경로** (`apps/web/src/routes/index.tsx`): 리다이렉트 대상을
  `satisfies FileRouteTypes['to']`로 선언해 존재하지 않는 경로가 컴파일 에러가 된다.
- **web ↔ bff 계약** (`packages/shared`): valibot 스키마를 한 곳에 두고 양쪽이
  `InferInput`으로 파생 타입을 쓴다. tRPC가 라우터 타입을 클라이언트까지 흘려보낸다.
- **DB 접근** (`apps/bff/src/platform/db/`): Kysely 타입드 SQL — 스키마 타입과
  어긋난 쿼리는 컴파일 에러다.

새 코드를 쓸 때 이 목록의 패턴을 우회하는 지름길(수동 replace, 캐스팅으로 통과시키기,
스키마 없이 문자열 하드코딩)을 추가하지 않는다.
