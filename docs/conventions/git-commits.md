# 커밋 컨벤션 — 태스크 단위 + 태스크 번호

**이 프로젝트에서 절대적으로 지킨다.** 모든 커밋은 태스크에 귀속되고, 커밋 메시지에
그 태스크 번호를 남긴다. git 이력만 봐도 "이 변경이 어느 태스크인가"가 즉시 드러나게 한다.

## 규칙

1. **한 커밋 = 하나의 태스크 범위.** 서로 다른 태스크의 변경을 한 커밋에 섞지 않는다.
   한 태스크가 여러 커밋으로 나뉘는 것은 허용한다(각 커밋에 같은 번호를 단다).
2. **제목 끝에 `(T0XX)`로 태스크 번호를 명시한다.** `git log --oneline`에서 바로 보이고
   `git log --grep=T0XX`로 태스크→커밋을 추적할 수 있게 한다. (PR 스쿼시가 붙이는
   `(#NN)`과 공존 가능: `… (T0XX) (#NN)`.)
3. 나머지는 사용자 글로벌 커밋 규칙을 그대로 따른다:
   - **제목**: 영어 Conventional Commits — `type(scope): subject (T0XX)`
   - **본문**: 한국어 "한다"체, 1~2줄 짧게, HEREDOC으로 작성
   - **AI attribution 절대 금지**: `Co-Authored-By: Claude …`, `🤖 Generated with …` 등
     어떤 형태의 AI 흔적도 넣지 않는다.

## 예

```
fix(bff): PGlite 데이터 디렉토리 부모까지 재귀 생성 (T026)

NodeFS가 leaf만 비재귀 mkdir 해 부모 없는 .data 아래에서 ENOENT로 죽던 것을,
파일 경로일 때 recursive mkdir로 선생성해 고친다.
```

## 태스크 문서와의 관계

- [docs/tasks/index.md](../tasks/index.md)의 규칙 4·5는 태스크 완료 시 **태스크 파일에
  커밋 해시를 기입**하도록 한다. 이 컨벤션은 그 반대 방향 — **커밋에 태스크 번호를
  기입** — 을 강제해 양방향으로 태스크↔커밋을 잇는다.
- 번호를 달 수 없는 변경은 원칙상 없다(모든 작업은 태스크로 시작한다). 부득이한 예외는
  태스크를 먼저 만든 뒤 커밋한다.
